# 验证记录

验证日期：2026-10-16，Windows 主机，Java 17.0.14，Docker Desktop 29.2.1。
项目使用 Spring Boot 3.5.16；数据库容器为 PostgreSQL 16。

执行 `mvn verify`，共 22 项测试，无失败、无错误、无跳过。

## 容器验收

使用 `docker compose up -d --build --wait`，四个容器均达到 healthy。
执行 `python scripts/smoke.py --chaos`，结果：

- 未认证请求返回 401。
- 提交、幂等重放、结果查询、执行记录与统计报表正确。
- 指定时间执行、运行中取消、Cron 生成实例与暂停通过。
- 执行过程中对 worker-a 发出 SIGKILL，随后停止该容器。
- worker-b 接管任务；执行记录依次为 LOST、SUCCEEDED，共两次执行。
- 恢复 worker-a，重启 PostgreSQL，原成功任务仍可查询。

## 本机短时测量

两个执行节点，每个 2 个槽位；API 与数据库在同一台 Docker Desktop 上。
先执行一轮 100 个任务的预热 / 功能测量，客户端并发 8，处理器为 sha256，文本 256 字节。

| 指标 | 实测 |
| --- | --- |
| 任务接入吞吐 | 833.37 请求 / 秒 |
| 接入延迟 P50 / P95 / P99 | 8.59 / 15.72 / 16.94 ms |
| 从提交到全部完成 | 0.901 秒 |
| 端到端任务吞吐 | 110.96 任务 / 秒 |
| 失败任务 | 0 |

随后以 1000 个任务、客户端并发 32 进行第二轮测量，处理器与数据大小不变：

| 指标 | 实测 |
| --- | --- |
| 任务接入吞吐 | 1248.15 请求 / 秒 |
| 接入延迟 P50 / P95 / P99 | 24.20 / 37.19 / 43.74 ms |
| 从提交到全部完成 | 3.752 秒 |
| 端到端任务吞吐 | 266.53 任务 / 秒 |
| 失败任务 | 0 |

以上为短时样本，包含客户端轮询与容器环境开销，不能视为系统容量上限或生产环境性能承诺。
接入吞吐和任务执行吞吐是不同指标。长耗时业务的吞吐受执行槽位与单次任务耗时约束。
复现脚本会输出原始 JSON，默认保存至 `target/benchmark.json`；不会输出应用密钥。
