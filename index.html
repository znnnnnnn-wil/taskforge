01 / 执行链路

从提交到接管

多节点部署中，PostgreSQL 保存任务、执行记录与租约，RabbitMQ 通知执行节点有新任务可领取。

阅读架构说明 ↗
  1. 01

    提交与触发

    通过 API 提交立即或延时任务，也可用六字段 Cron 和 IANA 时区生成周期实例。

  2. 02

    分发与领取

    事务 Outbox 保存待发送通知。Worker 收到消息后，按可用执行槽位领取任务。

  3. 03

    续租与恢复

    执行节点通过心跳续租。租约到期后，其他节点可接管任务，过期执行凭证无法写回结果。

02 / 核心能力

把调度细节留给平台

↻

可控重试

设置重试上限、指数退避与执行超时，支持按任务发起协作式取消。

⇌

幂等提交

用同一个请求标识和相同参数重试提交，避免重复创建任务。

≋

执行可追踪

从管理控制台查看进度、执行记录和节点状态，通过 Prometheus 采集指标。

交付语义　平台采用至少一次执行。涉及外部副作用时，业务处理器应按业务标识实现幂等。
